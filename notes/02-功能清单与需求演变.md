# 02 · 功能清单与需求演变

> 这一份是**需求考古**。页面上的很多设计看起来"有点怪"，但每一条都是用户明确提出并确认过的。
> 改交互之前先读这一页，否则很容易把已经拍板的东西改回去，然后再被要求改回来。

## 一、已经明确否决的设计（**不要加回来**）

| 曾经做过 | 为什么删 |
|---|---|
| 独立的 `expired.html` 过期项目页 | 用户原话「请去掉这个③新页面 expired.html。没有必要」。过期项目现在**直接不显示** |
| 首页副标题的「已过期 N 项」入口链接 | 同上，跟过期页一起删的 |
| 吸顶提示条（跳转后常驻显示「显示全部项目/收起」） | 用户要求「点项目后隐藏提示行」→「那行就不显示」 |
| 吸顶条里的「显示全部目录」按钮 | 用户要求取消 |
| 筛选「对象」里的「原住民」档 | 用户要求「对象里不要原住民」（该档只有 1 个项目，在「全部」里仍可查） |
| 过期页顶部「不能再申请，仅供查阅」横幅 | 跟过期页一起删 |
| 默认视图只显示「小企业可申请」 | 改成默认「全部」，否则筛选项上的数字和实际条数对不上 |

## 二、顶栏与页面骨架

演变过程（很有意思，能看出用户的真实关注点）：

```
第一版   品牌独占一行 + 副标题一行 + 搜索框一行 + 筛选行    → 手机上一屏看不到内容
第二版   搜索/关键词/目录/筛选 合并成一行（工具行）
第三版   品牌 + 搜索框 + 三个按钮同一行，省掉一整行；窄屏品牌缩成「🍁 补助库」
```

| 需求 | 实现 | 实现位置 |
|---|---|---|
| 手机上分类 chip 占屏太多 | 三组面板（关键词/目录/筛选）默认收起，点按钮才展开；且**互斥**——开一个自动关另外两个 | `togglePanel()` |
| 打开就要能看到目录（不是藏在按钮后面） | 目录面板默认展开，卡片列表同时隐藏（`VIEW_HIDDEN`），点目录项才显示正文 | `VIEW_HIDDEN` + `render()` |
| 搜索/目录/关键词/筛选放在一行 | 顶栏 `.bar` 用 `flex-wrap:nowrap` | `HTML_TPL` |
| 顶栏红色和 iOS 状态栏糊在一起 | 顶栏配色改为深藏蓝 `#1f3a5f`，并同步 `<meta name="theme-color">` | `NAV_BG` |
| 搜索框字比正文大 | `.bar input` 字号 14px，小于正文 16px | CSS |
| 顶栏上方出现网址行 | 那是 PWA 独立窗口模式的地址栏，非页面元素；已用 `apple-mobile-web-app-capable` 在"添加到主屏"后消除 | `<head>` meta |

## 三、目录（用户提了最多需求的地方）

| 需求 | 最终实现 |
|---|---|
| 要有目录 | `#tocPanel`，`columns:2`（窄屏 1 列） |
| 目录能跳转 | 每项是 `<a class="jump" href="#p-xxx">` |
| 点目录能隐藏项目 | 目录展开时 `VIEW_HIDDEN=true`，卡片全部 `display:none` |
| 目录项按 1,2,3 编号 | 单一连续编号，和正文卡片的 `.num` 完全对应 |
| 目录行只留「目录」两个字 | 按钮文字就是「目录」 |
| 点目录项后那行维持不动 | 不做吸顶条（已删） |
| 目录按钮本身是开关 | 展开时文字变「收起目录」，再点回「目录」（`syncTocBtn()`） |
| 点击后全部隐藏 | 即 `VIEW_HIDDEN` 机制 |
| **手机上第一个项目显示的是第三个** | 目录/正文顺序必须由**同一个数组**生成，编号也来自同一处 `progs_index` |
| **点目录不能直接跳到所选项目**（主屏 App 里） | 用同步 `window.scrollTo`，不用 `requestAnimationFrame`（PWA 窗口不触发）；跳转前先重置筛选和搜索，否则目标被筛掉没有落点 |

实现要点：

```python
# 目录和正文共用同一份排序结果
progs_index = {p["id"]: i for i, p in enumerate(progs)}
cards = "".join(card(p, i + 1) for i, p in enumerate(progs))
toc   = toc_block(progs, progs_index)
```

## 四、搜索与关键词

| 需求 | 实现 |
|---|---|
| 搜索框 | 顶部 `<input id="q">`，输入防抖 120ms |
| 搜索关键词要多 | `data-text` 索引：名称 + 中文名 + 机构 + 摘要 + 中文摘要 + 中文详情 + 资格 + 地区 + 全部关键词，小写后截 1200 字 |
| 要有可选的关键词 | 「关键词」按钮展开 `#hotPanel`，显示出现次数最多的 12 个标签 |
| 关键词面板空白过 | 标签改为**受控词表**（26 词）+ 同义归并，每个胶囊带数量 |
| 点关键词 → 填入搜索框 | 点一下 `setQ(kw)`；再点同一颗取消 |
| 关键词也隐藏 | 面板默认收起，由按钮控制 |

## 五、筛选

| 需求 | 实现 |
|---|---|
| 筛选选项几乎都不准确 | 三重修正：①受众按官方 `Recipient type` 判 ②安省项目逐条人工核对写进 `config/audience.json` ③每个选项显示**实时数量**（其它条件筛完还剩几条） |
| 搜索「关税」得 2 条，点「治安司法 4」却 0 条 | 修的是筛选叠加：分面计数时 `pass(card, skipGroup, q)` 跳过当前组自己 |
| 筛选里每组放一行 | `.fg{display:flex;flex-wrap:nowrap;overflow-x:auto}` |
| 对象选项「全部项目」放前面 | 每组第一个按钮固定是「全部」 |
| 对象里不要原住民 | 删掉该档 |
| 默认视图 | 全部（不预设「只看小企业」） |

四组筛选的取值：

| 组 | 取值 |
|---|---|
| 层级 `level` | `""` / `provincial` / `municipal` / `federal`（联邦档 11-25 随联邦项目加入） |
| 状态 `status` | `""` / `open` / `restricted` / `closed` |
| 对象 `aud` | `""` / `biz`（= business+mixed） / `nonprofit` / `gov`（= gov+indigenous） |
| 金额 `amt` | `""` / `lo`（≤5万） / `mid`（5-25万） / `hi`（>25万） |

## 六、卡片与详情

| 需求 | 实现 |
|---|---|
| 描述内容要更多 | 中文详情扩到 300-450 字，四段式：适用对象 / 资金用途 / 金额与自付 / 申请准备 |
| 点详情把文字提到顶端 | `<details>` 的 `toggle` 事件里 `window.scrollTo(0, top - 58)` |
| 每条都要有截止日或受理方式 | 五种写法，绝不留空（见 01 文档） |
| 每条标注核对日期 | 详情表最后一行「核对日期」= `last_verified` |

卡片结构（从上到下）：状态/金额/自付/截止标签 → 语言+层级标签 → 编号标题 → 英文原名 → 机构 → 中文摘要 → 关键词胶囊 → 可展开详情（正文 + 8-10 行元数据表）→ 底部链接（官方详情 / 咨询邮箱 / 回到目录）。

## 七、链接与外部跳转

| 需求 | 实现 |
|---|---|
| **「Original source / 搜索官方页面」要想到达要去的页面，而不是随便给一个页面** | 三级解析：项目自己的官方链接 → 猜址并校验标题 → 官方列表页 + `#:~:text=` 片段定位 |
| 仔细查链接（如 Forest Sector 应从标题开始） | 去掉 `#section-5` 这类中段锚点，`href.split("#")[0]` |
| 安省 Apply 按钮全是通用 TPON 页 | 排除 `get-funding-ontology-government` 和 `/search/`；块内打分挑专属页 |
| `forms.mgcs.gov.on.ca` 的 Program Guidelines 抓不到 | `OK_HOSTS` 加上 `gov.on.ca`，相对链接用 `urljoin` 补全 |
| `grants.gov.on.ca` 返回 502 | 每个候选链接都做 `verify_url()` 探活 |

## 八、数据与更新

| 需求 | 实现 |
|---|---|
| 显示页面更新时戳 | 副标题 + 页脚两处：**数据更新于**（抓取时间）+ **本页生成于**（构建时间），都是多伦多时间；手机上不隐藏 |
| 过期的不再显示 | `is_expired()` 过滤，不进首页 |
| 新建一页收集所有过期项目 | ~~已做~~ → **后被否决，删除** |
| 最近新增要能看到 | `changes.json` → `.newbox`，项目名是锚点链接，点了跳到对应卡片 |
| 文件时间是 9 点多、其他文件几天前，是否影响运行 | 不影响，时间戳只是 git 记录；真正的更新看 `data/programs.json` 的 `built_at` |

## 九、用户对「怎么做事」的偏好（比功能更重要）

1. **能自己查到的先查，别问。** 接口报错、超时、限流 → 自己换方案、降级、重试，然后汇报「出了什么事、我怎么处理的」。
2. **不要反复问「要不要重试」。**（明确讨厌）
3. **交付要能直接在手机上打开。** 优先给链接，其次给文件。
4. **界面/路径不明确时要澄清，不要瞎猜。**（这条和 1 不矛盾：查得到就查，查不到就问）
5. 中文沟通，结论先行。
