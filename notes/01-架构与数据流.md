# 01 · 架构与数据流

## 一、全景

```
                    ┌──────────────────────────────────────────┐
                    │  8 个官方源（唯一的真值来源）               │
                    │  · 安省 Available funding（h2 分块）       │
                    │  · 多伦多 Business Incentives（表格）      │
                    │  · 约克 2 / 荷顿 1 / 皮尔 2（人工核对的项目页）│
                    │  · 联邦 ISED · BEP 贷款基金（静态详情页）   │

                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  fetch_grants.py                         │
                    │  ├ parse_ontario()   h2 分块             │

                                    │
              ┌─────────────────────┴─────────────────────┐
              ▼                                           ▼
     data/programs.json                           data/changes.json
     51-52 条结构化数据                           与上一版比：新增/截止/状态/下架
     （含 first_seen / last_verified）             （首页「最近新增」用它）
              │                                           │
              └─────────────────────┬─────────────────────┘
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  build_site.py                           │
                    │  is_expired()  过滤掉过期                 │
                    │  render_page()  把数据塞进 HTML_TPL 模板  │
                    └───────────────┬──────────────────────────┘
                                    ▼
                  docs/index.html  +  docs/meta.json  +  docs/.nojekyll
                                    │
                                    ▼
                  GitHub Actions → deploy-pages（整站替换）
```

**关键结构：数据是一次性抓取、一次性构建的静态页。**
页面上的搜索、筛选、目录跳转**全部是前端 JS**，没有后端、没有数据库、没有 API 调用。
所以「加一个筛选条件」= 改 HTML 模板 + 一段 JS，不涉及任何服务。

## 二、`fetch_grants.py` 函数地图

| 函数 | 职责 | 关键细节 |
|---|---|---|
| `http_get(url)` | 统一 HTTP 入口 | 伪装 Chrome UA、`Accept-Language: en-CA`、手动解 gzip（标准库默认不自动解） |
| `strip_tags(s, limit)` | HTML 转纯文本 | **用空格替换标签**，否则 `<li>a</li><li>b</li>` 会拼成 `ab` |
| `fetch_detail_text(url, name)` | 抓详情页正文并清洗 | 取 `<main>`、砍 nav/footer/breadcrumb、从项目名首次出现处截掉页头 |
| `verify_url(url)` | 链接可达性检查 | 先 HEAD 后 GET，只要 2xx/3xx。**每个外链上线前都过这一关** |
| `pick_program_link(body, title, base)` | 从项目块里挑它**自己**的官方页 | 打分制：含 `guidelin` +5、`/dataset/` +4、`guide/criteria` +3……分数 ≥4 才进候选；按分数从高到低试，第一个能打开的就是它 |
| `guess_official_page(title)` | 按标题猜 `ontario.ca/page/<slug>` | 命中率低，**必须**用页面 `<title>` 校验：项目名实词覆盖 ≥60% 才用 |
| `listing_anchor(base, title, page_text)` | 生成 `#:~:text=` 文本片段 | 项目名含括号/冒号时整段匹配不上，先截到括号前，再从 6 词缩到 3 词，直到页面上确实存在 |
| `first_email(html)` | 抓咨询邮箱 | 从 `mailto:` 提取 |
| `parse_amount(text)` | 抽「单个申请人能拿多少」 | 见下方专节 |
| `parse_deadline(text)` | 抽日期 + 受理方式 | 见下方专节 |
| `parse_ontario(html, src)` | 安省页解析 | `html.split("<h2>")` 分块，每块内含 `Status:` / `Ministry` / `<h3>Deadline</h3>` / `<h3>Eligibility</h3>` |
| `parse_toronto(html, src)` | 多伦多页解析 | 严格匹配 `<tr><td><a>名称</a></td><td>描述</td><td>对象</td></tr>` 四段结构 |
| `parse_official_detail(html, src)` | 精选详情页解析（11-17 区级，11-25 扩到皮尔+联邦） | 约克 2 + 荷顿 1 + 皮尔 2 + 联邦 1 个**人工核对的官方项目页**，没有总表；`SOURCES` 里带 `body_selector` / 人工覆盖字段。`src` 里的 `amount_min`/`amount_max`、`how_to_apply` 可覆盖正则结果（用于官方原文句式非标准但金额明确的项目）。官网是零散项目页，所以用精选 URL + 每日刷新正文的方式，不假装能抓全 |
| `audience_from_recipient(s)` | 官方 Recipient type → 受众桶 | `business association` / `BIA` 是**协会不是企业**，判定前先剔除，否则会误判成小企业 |
| `audience_from_text(p)` | 从资格原文粗判 | 关键词法，仅作兜底 |
| `classify_audience(p)` | 三级判定入口 | 人工覆盖 → Recipient type → 资格原文 |
| `extract_keywords(p)` | 规则兜底标签 | `KW_VOCAB` 关键词命中，取前 5 |
| `norm_tags(tags)` | 标签归一化 | 同义归并（`TAG_ALIAS`）→ 丢弃词表外 → 去重保序，最多 4 个 |
| `translate(items, key, batch=5)` | Gemini 出中文 | 见下方专节 |

### 金额解析的四条规则

只认四种明确句式，其余一律不采信：

1. `maximum (amount) of $X` / `up to (a maximum of) $X`
2. `$X per project / per applicant / per business / per loan / per property`
3. `grant/loan/rebate/funding of $X`
4. 区间 `from $A to $B` / `between $A and $B`（且上下文不能是 project cost）

两道保险：

- **总规模排除**：数字后面 40 字符内出现 `program|fund|initiative|investment|envelope` → 判为基金总规模，跳过。
- **百分比排除**：`up to 90 percent of eligible costs` 会被百分比正则先吃掉（要求后面跟 `cost`），不进金额。
- **最后一道**：算出的上限 `< $100` 一律作废（`$90` 这种必然是百分比或笔误）。

### 截止日解析的优先级

```
① 明确日期     regex "Month DD, YYYY"  →  返回 ISO 日期 + kind="fixed"
② 说没有截止日  no deadline / ongoing / rolling / continuous / year-round  →  kind="rolling"
③ 分轮次       intake period(s) / intakes                                  →  kind="periodic"
④ 都没写                                                                   →  kind="unknown"
```

先补空格再匹配：`November 12<sup>th</sup>, 2026` 会变成 `November 12 th , 2026`，
用 `re.sub(r"(\d)\s+(st|nd|rd|th)\b", r"\1\2", ...)` 修回来。

注意 ③ 必须在 ② 之后判：「There are two application intake periods each year」
包含 `ongoing` 之外的词，但**不**是无期限，是分轮次。

### 翻译通道（可选）

```
GEMINI_API_KEY 存在？
├─ 否 → 跳过，页面英文（不报错、不中断）
└─ 是 → 先 GET /v1beta/models 拿可用模型列表
        （只要 flash 系、支持 generateContent、排除 image/tts/vision/embedding）
        按 5 条一批 POST generateContent
        每次只输出 JSON 数组：{"i":序号,"n":中文名,"s":一句话摘要,"d":四段详情,"t":[标签]}
        返回的标签再走 norm_tags() 压进 26 词受控词表
```

- `d` 固定四段：**适用对象 / 资金用途 / 金额与自付 / 申请准备**，300-450 字。
- 某段信息不足就写「以官方指南为准」，**不许省略该段**。
- 硬约束写进提示词：不准编造金额、日期、机构名。
- 模型列表按顺序试，第一个成功就 `break`；全失败只是没中文，不影响其他字段。

## 三、`build_site.py` 函数地图

| 函数 | 职责 |
|---|---|
| `money(v)` | 金额格式化：`$1.2M` / `$250K` / `$500` |
| `days_left(p)` | 距截止还有几天（负数=已过期） |
| `esc(s)` | HTML 转义 |
| `clip(text, n)` | **按句末标点**截断，避免「buying machiner」这种半句 |
| `anchor(p)` | 卡片锚点 id：`p-` + id 去掉非字母数字 + 取**末 48 字符** |
| `card(p, idx)` | 渲染一张卡片：标签行 / 标题 / 英文原名 / 机构 / 摘要 / 关键词 / `<details>` 详情表 / 底部链接 |
| `toc_block(progs, idx_map)` | 目录：**一条连续编号**，和正文编号一一对应，层级用小标签（省/市/联） |
| `is_expired(p)` | 过期判定：`status=="closed"` 或 `deadline < 今天` |
| `render_page(progs, *, title, sub, banner, new_html, empty_msg)` | 把一组项目塞进 `HTML_TPL` 返回整页 |
| `main()` | 读数据 → 过滤过期 → 排序 → 统计 → 写 `index.html` / `meta.json` / `.nojekyll` |

### 排序规则（`main()` 里）

```
小企业能申请的优先（business/mixed 排前）
  → 层级：省级 → 市级 → 联邦
  → 状态：开放优先
  → 截止日：快到的排前（无截止日排最后）
  → 金额：大额优先
```

### `HTML_TPL` 模板结构

```
<head>  CSS 变量（浅色/深色两套）→ 全部样式内联，无外部请求
<body>
  <div class="bar">     顶栏工具栏：品牌 + 搜索框 + 关键词/目录/筛选 三个按钮（一行）
  <div class="sub">     副标题：共 N 个 · 开放 N · 有金额 N · 有截止日 N + 数据更新时间
  __BANNER__            预留横幅位（当前未使用，但占位符必须替换，否则会显示字面量）
  #hotPanel             热门关键词胶囊（带出现次数）
  #tocPanel             目录（columns:2，窄屏 1 列）
  #filterPanel          四组筛选：层级 / 状态 / 对象 / 金额（每组一行，横向滚动）
  #count                当前显示条数
  __NEWBOX__            最近新增 N 项（项目名是锚点链接）
  __CARDS__             卡片列表
  <footer>              数据时间 + 生成时间 + 免责声明
<script>                搜索/筛选/目录/跳转全部在这儿，约 160 行原生 JS
```

前端 JS 的几个关键点：

- `pass(card, skipGroup, q)` —— 判断卡片是否通过筛选；分面计数时用 `skip` 跳过自己那一组。
- 每个筛选按钮上显示的数字 = **其它条件筛完之后该选项还剩几条**（避免「按钮说 20 条、点进去 3 条」）。
- `render()` 同时控制卡片显隐和按钮计数。
- 目录是**开关**：展开时按钮文字变「收起目录」，再点回「目录」。
- 点目录项 / 「最近新增」链接：先重置筛选 + 清搜索（否则目标被筛掉没有落点）→ 收目录 → `void el.offsetHeight` 强制布局 → **同步** `window.scrollTo` → 加 `.flash` 高亮 1.6 秒。
  **不能用 `requestAnimationFrame`**，PWA 独立窗口里不保证触发。

## 五、CI 机制（`.github/workflows/daily.yml`）

十个步骤，关键三个：

1. **恢复上次数据**：`actions/cache` 拿 `data/`（key `grants-data-<run_id>`，`restore-keys: grants-data-`）。
   ← 这是「data 不进 git 也能比对变更」的关键。
2. **抓取 + 构建**：`python3 fetch_grants.py && python3 build_site.py`。
3. **发布**：`upload-pages-artifact`（打包 `docs/`）→ `deploy-pages`（**整站替换**）。

两个闸门：

- 发布前自检：`docs/` 里出现 `<<<<<<<` 或 `>>>>>>>` 冲突标记就直接 fail。
- 打包必须在「归档」之前——归档时 rebase 冲突会把标记写进工作区。

权限只有 `contents: read` + `pages: write` + `id-token: write`，**没有写仓库的权限**——所以 CI 永远不会往 `main` 推提交，不会和本地抢文件。
