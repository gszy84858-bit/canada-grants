# 04 · 操作手册

## 一、本地运行

```bash
cd ~/Documents/GitHub/canada-grants
```

### 场景 A：只想看页面改得对不对（最常用，30 秒）

```bash
python3 build_site.py && open docs/index.html
```

用的是**已有的** `data/programs.json`，不联网、不抓取。
改 CSS、改卡片、改 JS 交互，全部走这条路。

### 场景 B：改了抓取或解析逻辑

```bash
python3 fetch_grants.py     # 2-4 分钟，会写出 raw/*.html 快照
python3 build_site.py
```

`data/programs.json` 会被覆盖。**如果只是想看抓取结果对不对，先备份一份**：

```bash
cp data/programs.json /tmp/programs.bak.json
```

### 场景 C：想测中文效果

```bash
GEMINI_API_KEY=你的key python3 fetch_grants.py
```

本机没有 key，这一步通常只能在 CI 里发生。不设 key 也能跑完，只是全英文——这是设计好的降级。

## 二、验证（每次改完都跑）

### 1. 结构自检（复制即用）

```bash
cd ~/Documents/GitHub/canada-grants && python3 - <<'EOF'
import json, re, collections
d = json.load(open('data/programs.json', encoding='utf-8'))
h = open('docs/index.html', encoding='utf-8').read()

print("项目总数:", len(d['programs']))
print("抓取错误:", d.get('errors') or "无")

# 卡片 id 唯一性（加信源后务必看这个）
ids = re.findall(r'<article class="card" id="([^"]+)"', h)
dup = [k for k, v in collections.Counter(ids).items() if v > 1]
print("卡片:", len(ids), "| 重复 id:", dup or "无")

# 所有跳转锚点都要有落点
bad = [a for a in re.findall(r'class="jump" href="#(p-[^"]+)"', h)
       if ('id="%s"' % a) not in h]
print("断掉的锚点:", bad or "无")

# 占位符没被替换（会直接在页面上显示 __XXX__）
left = re.findall(r'__[A-Z]+__', h)
print("未替换占位符:", set(left) or "无")

# 每条都必须有截止信息。
# 注意：deadline_kind == "unknown" 是**合法**的兜底值，页面会显示「截止日见官方页」。
# 只报「连 kind 都没有」的，那才是真的漏了。
no_ddl = [p['name'] for p in d['programs']
          if not p.get('deadline') and not p.get('deadline_kind')]
print("缺截止信息:", no_ddl or "无")

# 链接健康度
no_link = [p['name'] for p in d['programs'] if not p.get('url') and not p.get('anchor_url')]
print("两条链接都没有:", no_link or "无")
EOF
```

期望全部输出「无」。`未替换占位符` 出现任何东西都是 bug（最常见的是 `__BANNER__` 忘了传参）。

### 2. 手机上真机看

改完页面**必须**在手机宽度下看一遍（用户主要用手机）。Chrome DevTools 切 390px，或直接推到线上后用手机开。
重点看：顶栏是否挤成两行、目录按钮文字切换、卡片内长英文名是否溢出。

## 三、改动 → 上线 的完整流程

```
① 改代码（Read → Edit，不要用字符串切片）
② python3 build_site.py && open docs/index.html
③ 跑第二节的结构自检
④ git add -A && git commit -m "一句话说清改了什么、为什么"
⑤ git push origin main      ← 本机已具备凭据（11-24 实测可直接推；失效时才找用户点 Push）
⑥ push 后自动触发 CI（build_site.py 在触发路径里）
⑦ 3-5 分钟后核线上：curl meta.json 看 count / built_at
```

线上核对命令：

```bash
curl -s https://gszy84858-bit.github.io/canada-grants/meta.json
curl -s -o /dev/null -w "%{http_code}\n" https://gszy84858-bit.github.io/canada-grants/
```

### 提交信息风格

一直以来的写法是**说清「改了什么 + 为什么」**，不用 `fix` / `update` 这种词：

```
去掉 expired.html：已过期项目直接不展示，不再单列一页，首页副标题也移除入口
最近新增的项目名做成链接：点了直接落到那张卡片（复用目录的跳转逻辑，自动清空筛选与搜索）
官方链接重做：抓项目块自己的官方页(含 forms.mgcs 指南)、猜址必校验、无页则用官方资金页文本片段精确定位
```

### CI 触发条件（`daily.yml` 的 `on.push.paths`）

只有改这三个才触发 push 构建：

- `fetch_grants.py`
- `build_site.py`
- `.github/workflows/*.yml`

**改 `config/audience.json`、`README.md`、`HANDOVER.md` 不会触发。**
如果改的是受众覆盖表，要么等第二天定时跑，要么去 Actions 页面手动 **Run workflow**。

## 四、从零复现（如果整个项目丢了）

按这五个阶段走，顺序别乱——每一步都建立在上一步验证通过的基础上。

### 阶段 1 · MVP 跑通（对应 `f767237`）

**目标**：能把两个官方页抓成 JSON，再渲染成一个能看的 HTML。（后来扩到 5 个源，阶段 1 只需 2 个）

1. 建仓库，开 Pages（Settings → Pages → Source 选 **GitHub Actions**）。
   免费账号只能用**公开**仓库。
2. `fetch_grants.py`：`SOURCES` 两条 + `http_get` + `strip_tags` + `parse_ontario` + `parse_toronto` + 去重 + 写 JSON。
3. `build_site.py`：一个 `HTML_TPL` + `card()` + 简单 `render`。
4. `.github/workflows/daily.yml`：checkout → setup-python → fetch → build → upload-pages-artifact → deploy-pages。
5. 验收：`python3 fetch_grants.py` 输出「50 个项目」，页面能打开。

### 阶段 2 · 页面能用了（对应 `48fda58`）

1. 目录 `toc_block()` + 卡片锚点 `anchor()`，两者用**同一个数组**生成编号。
2. 热门关键词 `#hotPanel`（按 `keywords` 词频取前 12）。
3. 每条可展开详情 `<details>`，里面表格放金额/自付/截止/资格/怎么申请。
4. 搜索索引扩到包含详情和关键词（`data-text`）。

**验收**：点目录第 5 项，落到第 5 张卡片，编号一致。

### 阶段 3 · 交互打磨（`0d675a8` → `1d9ddbb` → `91225c2`）

1. 顶栏合并成一行：品牌 + 搜索框 + 三个按钮。
2. 三组面板互斥展开（`togglePanel` 里先全关再开目标）。
3. 筛选每组压成一行，横向滚动，金额档位缩写。
4. 目录按钮即开关（「目录」↔「收起目录」）。
5. 目录展开时隐藏卡片列表（`VIEW_HIDDEN`）。

**验收**：390px 宽下顶栏不换行；点「目录」文字变成「收起目录」。

### 阶段 4 · 数据准确性（`a8e49b5` → `7793479` → `8331831`）

这是项目从"能用"到"可信"的分水岭，也是最费时间的一段。

1. 受众三级判定 + `config/audience.json` 人工覆盖（安省 22 条逐条核对）。
2. 筛选默认「全部」+ 分面计数（每个按钮显示其它条件筛完的剩余数）。
3. 官方链接三级解析（项目自己 → 猜址校验 → 文本片段定位）+ 每个链接探活。
4. 截止日五态（明确日期 / 滚动 / 常年 / 分轮次 / 见官方页），绝不留空。
5. 金额只认四种明确句式，排除总规模和百分比。

**验收**：随便抽 5 条，点「官方详情」都能落到该项目自己的页面；每条都有截止状态。

### 阶段 5 · 时效与收尾（`67155ba` → `c9b15fb` → `982cb86`）

1. 页面上显示「数据更新于 / 本页生成于」（多伦多时间，手机上不隐藏）。
2. 过期项目处理：**先做过独立页，后来按用户要求删掉，改成直接不显示**。
3. `changes.json` → 「最近新增 N 项」，项目名做成锚点链接。

**验收**：`meta.json` 的 `built_at` 每天在变；新增项目显示在列表顶部。

## 五、故障排查

| 现象 | 先看这里 |
|---|---|
| 页面空白 / 样式全丢 | 构建有没有报错；`docs/index.html` 里搜 `__` 看有没有未替换占位符 |
| 页面上出现 `__BANNER__` 字样 | `render_page()` 的 `banner` 参数没传——模板占位符必须被 replace，哪怕是空字符串 |
| 某个信源抓不到 | 跑 `fetch_grants.py` 看「抓取失败」那行；多半是官网改版，解析正则要跟着改 |
| 条数突然掉一半 | 先看 `raw/*.html` 快照，用浏览器打开对照；常见是页面结构从 `<h2>` 变成了 `<div>` |
| 金额全是 null | `parse_amount` 的句式正则被官网改写了，去看 `deadline_text` / `desc` 原文 |
| 线上没更新 | 先看线上 `meta.json` 的 `built_at`，再看 CI 是否失败（Actions 页）；或改的文件不在 `paths` 触发列表里。若失败日志是 `No artifacts named "github-pages"`，是产物 API 短暂滞后，工作流已加轮询等待闸门（11-24 修复） |
| 又提示 Pull origin | 说明有人在往仓库推数据——检查 `data/` 是否被意外提交进 git（应该在 `.gitignore` 里） |
| push 报 could not read Username | 凭据失效了。让用户在 VS Code 点 Push，或 `⌘⇧P` → `Git: Push` |
