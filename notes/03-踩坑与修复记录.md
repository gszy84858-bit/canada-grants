# 03 · 踩坑与修复记录

> 36 次提交，几乎每一次都在修一个具体的坑。这一页按「症状」组织——遇到怪现象就直接搜关键词。
> 每条都写清：**症状 → 根因 → 修法**。标了提交号的可去 `git show <hash>` 看完整改动。

## A. 抓取与 HTTP

### A1 · 相对链接全被丢掉
**症状**：`forms.mgcs.gov.on.ca` 上的 Program Guidelines 一个都抓不到，43 个项目退化成「搜索官方页面」。
**根因**：项目块里的链接写成 `/page/xxx`（相对路径）。代码只认 `host` 在白名单里的绝对 URL，`urlparse("/page/xxx").netloc` 是空字符串 → 直接被 `_host_ok()` 判掉。
**修法**：处理前先 `urllib.parse.urljoin(base_url, href)` 补全，白名单同时加上 `gov.on.ca`（覆盖 `forms.mgcs.` / `tpon.` 等子域）。`7793479`

### A2 · 官方页里留着已停用的旧链接
**症状**：点「官方详情」跳 502。
**根因**：Ontario Grants Portal（`grants.gov.on.ca`）已停用，但安省页面上的按钮还指着它。
**修法**：`verify_url()` 先 HEAD 后 GET 探活，2xx/3xx 才算数；候选按分数排序后**逐个试，第一个能打开的才用**。`7793479`

### A3 · 所有项目的 Apply 按钮指向同一个页面
**症状**：43 个安省项目的「官方详情」全跳 TPON 登录页，信息量为零。
**根因**：安省页面每个项目块的 Apply 按钮都是同一套通用申请系统入口。
**修法**：排除 `get-funding-ontario-government` 和 `/search/`，改为在块内给所有链接打分（`guidelin` +5、`/dataset/` +4、`guide/criteria` +3 ……）；分数 ≥4 才进候选。`7793479`

### A4 · 猜官方页命中率只有 1/6
**症状**：按标题拼 `ontario.ca/page/<slug>`，8 个里只中 1 个，其余全是 404 或完全不相干的页面。
**修法**：**必须校验**——抓回页面的 `<title>`，项目名实词覆盖率 ≥60% 才采用，否则宁可不给。`7793479`

### A5 · 链接从文章中间开始展示
**症状**：点进去页面停在「Section 5」中间，用户还得自己往上滚。
**根因**：官方链接自带 `#section-5` 这类中段锚点。
**修法**：`href.split("#")[0]` 去掉所有 fragment（`#:~:text=` 是后来自己拼的，不受影响）。`8331831`

### A6 · gzip 响应乱码
**症状**：`UnicodeDecodeError` 或返回一堆乱码。
**根因**：标准库 `urllib` 不会自动解 gzip，而请求头里声明了 `Accept-Encoding: gzip`。
**修法**：手动判断 `Content-Encoding` 后 `gzip.decompress()`。

### A7 · 文本拼接少空格
**症状**：摘要里出现 `machineryThe` 这种粘连词。
**根因**：`strip_tags()` 用空字符串替换标签，`<li>a</li><li>b</li>` → `ab`。
**修法**：**用空格替换标签**，再 `re.sub(r"\s+", " ", ...)` 归一化。`a8e49b5`

### A8 · 「联邦项目要浏览器渲染」是试错域名得出的错误结论
**症状**：接手文档长期写着「BBF 需浏览器渲染，零依赖做不到」，联邦源一直没做。
**根因**：当时抓的是 `www.canada.ca/...`，标准库请求直接超时；但同一个联邦项目在
ISED 站点 `ised-isde.canada.ca/site/ised/en/programs-and-initiatives/black-entrepreneurship-program/...`
是**静态 HTML**，`http_get()` 20 秒内能完整拿到正文（含 `$10,000 to $250,000` 原文）。
**修法（2026-11-25）**：新增 `fed-bep-loan` 源，走 `parse_official_detail()`；
官方原文用 `between $10,000 to $250,000` 句式，`parse_amount()` 抓不到，
在 SOURCES 里人工核对后写 `amount_min`/`amount_max` 覆盖，并在 `amount_note` 标明「贷款非赠与」。
**教训**：判断「抓不到」之前先换同一机构的官方域名试一遍，别把超时当成渲染依赖。

## B. 字段解析

### B1 · 序数词被 `<sup>` 拆散
**症状**：`November 12, 2026` 匹配不上，截止日全空。
**根因**：原始 HTML 是 `November 12<sup>th</sup>, 2026`，转纯文本后变成 `November 12 th , 2026`。
**修法**：匹配前 `re.sub(r"(\d)\s+(st|nd|rd|th)\b", r"\1\2", t)`。

### B2 · 把百分比当成金额
**症状**：某项目显示「上限 $90」。
**根因**：原文 `up to 90 percent of eligible costs`。
**修法**：①百分比正则要求后面 45 字符内出现 `cost` → 归到 `cost_share` 字段；②金额上限 `< $100` 一律作废。

### B3 · 把基金总规模当成单笔上限
**症状**：某项目显示「上限 $500M」，实际单笔最多几万。
**根因**：原文 `a $500 million program that provides funding to...`。
**修法**：数字后面 40 字符内出现 `program|fund|initiative|investment|envelope` → 判为总规模，跳过（`is_total()`）。

### B4 · 把项目成本区间当成补助区间
**症状**：`from $50,000 to $500,000` 被当成能拿的钱。
**根因**：原文说的是「合格项目成本区间」。
**修法**：区间匹配后检查前 90 字符，出现 `cost|costs|project size|capital projects` → 不采信。

### B5 · 「分轮次受理」被当成「无期限」
**症状**：每年只开放两轮的项目显示「滚动受理」，用户以为随时能申请。
**根因**：`intake periods` 里没有 rolling 关键词，但代码先判了「没写日期 = rolling」。
**修法**：`intake period(s)` / `intakes` 单独判成 `periodic`（分轮次），优先级在 rolling 之后、unknown 之前。

### B6 · 中文标签成了自由发挥
**症状**：同一类项目标签五花八门（`基建` / `基础设施` / `基建项目`），热门关键词面板全是碎片。
**修法**：26 词受控词表 `TAG_VOCAB` + 同义词归并表 `TAG_ALIAS` + `norm_tags()` 三级过滤（归并 → 丢词表外 → 去重），最多 4 个。`98779e0`

### B7 · 规则兜底标签全被丢掉，部分项目 keywords 为空
**症状**：9/59 条项目 `keywords` 为空，热门关键词面板少几项。
**根因**：`extract_keywords()` 的 `KW_VOCAB` 键写成了「设备 / 研发 / 能效 / 租金 / 新创 / 雇佣」，
而最终统一过 `norm_tags()`（只认 `TAG_VOCAB` 的「设备采购 / 研发创新 / 节能环保 /
租金房产税 / 初创企业 / 雇工补贴」）——规则命中的标签全部被静默过滤，且没有任何报错。
**修法（2026-11-25）**：`KW_VOCAB` 的键改成受控词表内的词，并补
「建筑地产 / 基础设施 / 交通物流 / 文化艺术」的命中词（`road`、`pothole`、
`tax rebate`、`development charge`、`heritage` 等）；同时收窄过宽的 `capital`/`job` 命中词，
避免给无关项目乱贴标签。本地全量抓取 60 条，空关键词从 9 条降到 **0 条**。

## C. 受众判定

### C1 · 协会被当成小企业
**症状**：`BIA`（Business Improvement Area）、商会这类机构项目出现在「小企业可申请」里。
**根因**：`"business association"` 里含 `business`，关键词命中了。
**修法**：判定前先把 `business association` / `business improvement (area)` 这几个短语**从字符串里删掉**再判 `has_biz`；同时单独标记 `has_bia`。`a8e49b5`

### C2 · 筛选项数字和实际条数对不上
**症状**：按钮写「对象 · 小企业 18」，点进去只有 2 条。
**根因**：数字是静态写的，不随其它筛选条件变化。
**修法**：改成**分面计数**——算某组某个选项的数字时，`pass(card, skipGroup, q)` 跳过该组自己，只应用其它条件。

### C3 · 默认筛选导致数字全错
**症状**：总数 50，但各档加起来对不上。
**根因**：默认视图预设了「只看小企业」。
**修法**：默认改「全部」，数字即全库真实数量（22+28=50 / 44+5+1=50 / 27+5+18=50）。`425d834`

## D. 前端

### D1 · `requestAnimationFrame` 在 PWA 里不触发
**症状**：主屏 App 里点目录项，页面不滚动（浏览器里正常）。
**根因**：独立窗口 / 后台标签页里 rAF 回调被节流或丢弃。
**修法**：改**同步**执行——先 `void el.offsetHeight` 强制完成布局，再 `window.scrollTo(0, y)`。`e3f8e85`

### D2 · 点目录项跳到错误位置 / 跳不到
**症状**：明明点了第 5 项，落到第 3 项；或者点了没反应。
**根因**：①目录和正文用两套顺序生成，编号错位；②目标卡片被当前筛选条件隐藏了，页面上没有落点。
**修法**：①目录和正文由**同一个 `progs` 数组**生成，编号来自同一个 `progs_index`；②跳转前先 `F = {level:"",status:"",amt:"",aud:""}`、`Q = ""`、清空搜索框，再 `render()`。

### D3 · 详情展开后要手动往上滑
**症状**：点开「详情」，展开的内容在视口上方，用户看不到。
**修法**：`details` 的 `toggle` 事件里 `window.scrollTo(0, top - 58)`。

### D4 · 搜索框字比正文大
**症状**：手机上搜索框文字显得突兀。
**根因**：`input` 继承 body 的 16px，而卡片正文是 14.5px。
**修法**：`.bar input` 显式设 14px。

### D5 · 窄屏按钮文字被截断
**症状**：手机上「目录」变「收起目录」后，搜索框 placeholder 被挤成「搜索项…」。
**修法**：`window.innerWidth < 480` 时把 placeholder 换成短版「搜索项目」。

### D6 · 关键词面板一片空白
**症状**：点「关键词」展开，里面什么都没有。
**根因**：`.hot` 被设了 `display:none`，而面板展开不会覆盖它。
**修法**：`.hot` 恢复 `display:flex`，显隐完全交给面板的 `.open` 类。

### D7 · Python 字符串吃掉 JS 的换行
**症状**：模板里 `var x = "a\nb"` 生成出来变成真换行，JS 语法错误，整页脚本挂掉。
**根因**：`HTML_TPL` 是 Python 三引号字符串，`\n` 在 Python 阶段就被解释了。
**修法**：需要换行符的地方用 `String.fromCharCode(10)`。**改模板 JS 时务必本地构建后打开页面看控制台。**

### D8 · 卡片 `id` 重复导致跳转落到错的卡片
**症状**：点某两条目录项，都跳到同一张卡片。
**根因**：`anchor()` 取 id 的末 48 字符，同源长名字截断后可能撞车。
**修法**：目前 52 条实测无重复（有校验脚本，见 `notes/04`），但加信源后**必须重新校验一次**。

## E. CI 与 Git

### E1 · 本地和云端天天抢同一个文件
**症状**：每次打开 VS Code 都提示 Pull origin；`git push` 被拒（non-fast-forward）。
**根因**：CI 每天提交 `data/programs.json`，本地也在改同一份。
**修法（三步走）**：
1. 先给 `data/*.json` 设 `merge=ours`（`.gitattributes`）——治标，不冲突了但每天多一个无意义提交；
2. 最终方案：`data/` 加入 `.gitignore`，改用 **Actions 缓存**跨天传递快照；
3. CI 权限收紧到 `contents: read`，**根本没有推送能力**。`c3ae135`

### E2 · 删页面必须靠 CI 重建
**症状**：本地删了 `docs/expired.html` 并提交，线上还在。
**根因**：`docs/` 在 `.gitignore` 里，删文件这个动作根本没进 git。
**修法**：改**生成器**（`build_site.py`）让它不再生成，然后 push 触发 CI。`deploy-pages` 是整站替换，旧文件自动消失。`c9b15fb`

### E3 · 页面顶部多出一行网址
**症状**：手机上打开，顶部有一条 URL 栏。
**根因**：Safari 直接打开网页会显示地址栏；「添加到主屏」后才会全屏。
**修法**：`<meta name="apple-mobile-web-app-capable" content="yes">` + `theme-color` 与顶栏同色。

### E4 · Pages 首次部署前 API 返回 404
**症状**：自检脚本判断「Pages 未启用」，实际是首次部署还没完成。
**修法**：首次部署前后 API 返回 404 是正常的，以 `deploy-pages` 步骤的结果为准。

### E5 · 定时任务总是晚几个小时
**症状**：cron 写的是 `0 10 * * *`（多伦多 5-6 点），早上打开还是昨天的数据，
Actions 里实际运行时间在 16-20 UTC（多伦多中午到下午）。
**根因**：GitHub 免费层 schedule 资源紧张时会排队、降级，时间完全不保证。
**修法**：**不要改 cron 去追**，改了也不会准时。这是平台行为。
要真准时只能外部定时服务（cron-job.org 等）定时打 `workflow_dispatch` 接口。
日常判断「有没有更新」看 `meta.json` 的 `built_at`，别看时钟。

## F. 协作与工具（给下一个 AI 看）

### F1 · 用字符串切片改代码，把文件写坏
**症状**：`fetch_grants.py` 被改成了语法错误的碎片。
**根因**：用 `s[:i] + new + s[j:]` 这种索引切片替换，索引算错一次就毁文件。
**修法**：①永远先 `Read` 再用精确 `Edit`（`old_string` 唯一匹配）；②真要脚本改，加 `assert s.count(old) == 1`；③坏了立刻 `git checkout -- <file>` 恢复，别试图手工拼回去。

### E6 · 产物上传成功，deploy-pages 却说「找不到产物」
**症状**：2026-11-23、11-24 连续两天 CI 失败，线上停在 11-22。失败日志：
`Found 0 artifact(s)` → `Error: No artifacts named "github-pages" were found for this workflow run`。
**根因**：`actions/upload-artifact@v4` 日志显示产物已成功上传（API 查询也能看到 artifact id），
但 `actions/deploy-pages@v4` 在上传完成 0.5 秒后就查 API，偶发读到旧的列表。11-22 成功时同样是 0.5 秒，只是那次没撞上。GitHub 状态页显示 All Systems Operational，不是平台故障。
**修法**：打包和发布之间加一步「等待 Pages 产物在 API 中可见」——用 `gh api` 轮询
`actions/runs/$GITHUB_RUN_ID/artifacts`，最多 12 次 × 10 秒，看到 `github-pages` 才继续。`340f32e`
**验证**：推送触发的 CI（run 45524299533）全部步骤绿，线上 `meta.json` 的 `built_at` 前进到 11-24 20:18。
**顺带**：第一次推送这个修复被 GitHub 拒绝——`refusing to allow an OAuth App to create or update workflow ... without workflow scope`。
当天用 `gh auth refresh -s workflow` 走设备码授权补上 scope 后推送成功；该令牌同时被 git 的 osxkeychain 凭据使用。

### F2 · 本机推送凭据的前后变化（注意别用旧结论）
**2026-10-28 时**：钥匙串无 github.com 条目、没装 `gh`、`~/.ssh` 是空的，
`git push` 报 `could not read Username`，只能让用户在 VS Code 点 Push origin。

**2026-11-24 起已改变**：装上了 `gh` CLI，`git credential fill` 能返回 github.com 凭据，
`git push origin main` 实测成功（推了 `1c6d064..59cb5c3`）。同日晚些时候又补上了 `workflow` scope
（设备码授权；gh 与 git 用的是同一个令牌，授权后 git 凭据自动同步），所以工作流文件也能直接推。
**现在改完直接自己推**，别再麻烦用户。只有凭据再次失效时才退回老办法
（让用户点 Push，或 `⌘⇧P` → `Git: Push`）。

### F3 · 本地跑出来的页面全是英文
**现象**：`programs.json` 里 52 条全无 `zh_name`。
**根因**：本机没有 `GEMINI_API_KEY`，翻译被跳过（这是设计好的降级，不是 bug）。
**结论**：本地验证**看结构和交互**，中文效果只能看线上。别为了本地测中文去折腾 key。
